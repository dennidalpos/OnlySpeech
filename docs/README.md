# Documentation Map

This directory contains technical, operational, customer-bundle, and product-supporting documentation that is verifiable from the repository. The root `README.md` is a GitHub-facing storefront summary only; it is not the technical command, CI, packaging, or release contract.

## Canonical Order

Use these sources in order when exact behavior matters:

1. repository code, tests, scripts, config, and workflow files;
2. `package.json` for npm entrypoints and package metadata;
3. `.github/workflows/` for CI and tagged-release behavior;
4. `docs/PROJECT_SPEC.md` for the long-form repository contract;
5. `scripts/README.md` for the PowerShell script index and side effects;
6. `PROJECT_STATUS.json` for current external blockers and open verification work.

Prefer npm entrypoints from `package.json` over direct internal script paths unless a document is explicitly describing internal implementation.

## Current Documents

- `docs/PROJECT_SPEC.md`: runtime, configuration, verification, packaging, output, and release boundaries.
- `scripts/README.md`: public wrappers, internal script ownership, and script side effects.
- `docs/product/provider-setup.md`: Azure and ChatGPT provider setup boundaries plus official documentation links.
- `docs/product/Marketplace_Sales_Package.md`: seller-facing marketplace positioning and bundle contents.
- `docs/product/screenshots/`: tracked product screenshots regenerated by `npm run docs:screenshots`.
- `docs/customer-bundle/`: buyer-facing documents copied by `npm run release:customer-bundle`.
- `docs/internal/`: repository-only policy and manual verification runbooks.
- `docs/decisions/`: accepted decisions that define implemented repository contracts or durable constraints.

## Documentation Boundaries

- Keep README-level product copy, buyer-facing bundle copy, and seller-facing marketplace copy separate.
- Do not mirror Azure, OpenAI, Electron, npm, GitHub Actions, or Windows documentation. Link to official docs and document only the repository-specific boundary.
- Keep CI, testing, release, packaging, architecture, and maintenance detail out of the root README.
- Keep generated outputs out of documentation unless the repository scripts generate or retain them.

## Generated Outputs Referenced By Docs

- `dist/`: TypeScript/Vite build output.
- `artifacts/packages/`: Windows installer, portable executable, and retained unpacked archive.
- `artifacts/logs/`: release evidence, third-party notices, SBOM, activation validation, commissioning evidence, and runtime-log exports.
- `artifacts/build/`: transient verification and packaging working data.
- `media/marketplace-demo/`: marketplace demo generation target; the repository currently tracks the README there, and `scripts/internal/docs/write-product-demo-video.ps1` writes the MP4/poster when marketplace video collateral is being prepared.

## Repository Contracts Referenced By Docs

- Runtime env keys and secure-key metadata: `src/shared/runtime-env-contract.ts`.
- Env parsing and normalization: `src/shared/config.ts`, `src/shared/runtime-env-normalization.ts`.
- IPC payload validation shared by Electron IPC and HTTP automation: `src/main/ipc.ts`, `src/main/ipc-payloads.ts`, and `src/main/test-automation.ts`.
- Packaged runtime paths and secure secret behavior: `src/main/runtime-paths.ts`, `src/main/runtime-secrets.ts`.
- Activation validation and shared license copy: `src/main/activation-validator.ts`, `src/shared/license-copy.ts`, `src/shared/license-form.ts`.
- Setup wizard behavior: `src/main/setup-wizard-manager.ts`, `src/main/setup-wizard-autostart.ts`, `src/main/setup-wizard-runtime.ts`, and `src/tools/setup-wizard/`.
- Repo-owned helper tooling: `tooling/`.
- Local or vendored tool payloads: `tools/`, outside the packaged runtime contract unless explicitly documented elsewhere.
