# Documentation Map

This directory contains the technical and operational documentation that is evidenced by the repository. The root `README.md` is a GitHub-facing storefront summary only; it is not the technical command, CI, packaging, or release contract.

## Source Of Truth

Use these sources in order when exact behavior matters:

1. repository code, tests, scripts, config, and workflow files;
2. `package.json` for npm entrypoints and package metadata;
3. `.github/workflows/` for CI and tagged-release behavior;
4. `docs/PROJECT_SPEC.md` for the long-form repository contract;
5. `scripts/README.md` for the PowerShell script index and side effects;
6. `PROJECT_STATUS.json` for the residual backlog only.

Prefer npm entrypoints from `package.json` over direct internal script paths unless a document is explicitly describing internal implementation.

## Technical Documents

- `docs/PROJECT_SPEC.md`: runtime, configuration, verification, packaging, output, and release boundaries.
- `scripts/README.md`: public wrappers, internal script ownership, and script side effects.
- `docs/product/provider-setup.md`: provider setup boundary plus official Azure/OpenAI references.
- `docs/internal/testing/packaged-activation-commissioning-runbook.md`: real-workstation activation and commissioning close-out.
- `docs/internal/testing/language-speech-matrix.md`: retained manual live-provider speech proof matrix.
- `docs/decisions/`: accepted decisions that define durable repository constraints.

## Supporting Documents

- `docs/customer-bundle/`: buyer-facing documents copied by `npm run release:customer-bundle`.
- `docs/product/Marketplace_Sales_Package.md`: seller-facing marketplace positioning and bundle contents.
- `docs/product/screenshots/`: tracked screenshots regenerated by `npm run docs:screenshots`.
- `docs/internal/Privacy_and_Commercial_Distribution.md`: repository privacy and commercial-distribution boundary.

## Documentation Rules

- Keep product-facing copy in the root README and technical detail in docs.
- Do not mirror Azure, OpenAI, Electron, npm, GitHub Actions, or Windows documentation; link out and keep only repository-specific boundaries.
- Keep generated outputs in docs only when repository scripts create or retain them as part of the contract.

## Generated Outputs Referenced By Docs

- `dist/`: TypeScript and Vite build output.
- `artifacts/packages/`: Windows installer, portable executable, and retained unpacked archive.
- `artifacts/logs/`: release evidence, notices, SBOM, activation validation, commissioning evidence, and optional runtime-log exports.
- `artifacts/build/`: transient verification and packaging working data.
- `media/marketplace-demo/`: marketplace demo collateral target; `scripts/internal/docs/write-product-demo-video.ps1` writes the MP4/poster when that collateral is being prepared.
